# Локальный модуль ЕСТД

Модуль читает PDF, определяет тип карты по обозначению в рамке и извлекает две графы со ссылками на исходные фрагменты. Вызывающая программа может передать целый документ или несколько физических страниц. Обработка выполняется локально на CPU.

## Подключение

Из корня репозитория установите пакет командой `python -m pip install ./estd` в окружение Python 3.11 или новее. Для автономной установки заранее сложите wheel пакета и всех зависимостей в каталог и выполните `python -m pip install --no-index --find-links ./wheels ai-gosts-estd`. Для сканов передайте каталог с локальным файлом `rus.traineddata` через `tessdata` или `TESSDATA_PREFIX`. Если OCR недоступен, страницы, на которых он понадобился, получают диагностическое сообщение.

```python
from estd import analyze_pdf, capabilities

supported = capabilities()
result = analyze_pdf("отчет.pdf", output_dir="проверки", tessdata="tessdata")
for page in result.report["pages"]:
    form = page.get("form", {})
    field = page["fields"]["profile_size"]
    value = field["value"] or {}
    print(page["page"], form.get("code"), field["status"], value.get("text"))
print(result.directory / "index.html")
```

Для отдельных листов укажите, например, `pages=[109, 115]`. Каждый вызов получает новый каталог с `result.json`, HTML и вырезками. Прежние команды `scripts/inspect_route_card.py` и `scripts/inspect_route_batch.py` используют тот же обработчик.

## Контракт v1

* На уровне документа возвращаются `module`, `schema_version`, имя и SHA-256 PDF, список страниц и `supported_form_found` для выбранных страниц. Будущий диспетчер ЕСТД, ЕСКД и ЕСПД может получить перечень возможностей через `capabilities()` и передавать сюда подходящие страницы смешанного отчёта.
* Если в ячейке распознан код МК, ОК или КЭ, `page.form` содержит тип формы, код, метод чтения, координаты и путь к вырезке. Отсутствие `form` означает, что тип остался неизвестен. Поиск граф выполняется и на таких листах.
* `fields.designation` относится к обозначениям в первой найденной строке А. `fields.profile_size` относится к значению под заголовком «Профиль и размеры». Для заголовка и значения доступны рамки, изображение, извлечённый текст и метод чтения. Координаты отсчитываются от левого верхнего угла исходной страницы PDF. Вырезки показывают графы после автоповорота.
* Статус `located` означает, что рамка значения выделена. Если текст пуст, содержимое следует проверить по вырезке. `header_only` означает, что найден заголовок, `review` требует просмотра листа. На подтверждённой карте эскизов отсутствующая графа профиля получает `not_applicable`.
* `normative_references` содержит учебные вопросы, ответы и ссылки на редакцию, пункт, физическую страницу и SHA-256 источника. Четыре записи для МК сверены по пп. 1.1, 2.2 и графам 10 и 19 таблицы 4 ГОСТ 3.1118-82, переиздание февраля 2012 года. На страницах МК `field_references` связывает каждую из двух граф с её описанием в таблице 4. Те же записи доступны через `estd.normative_references("МК")`. Для остальных форм список пока пуст. Статус действия редакции и соответствие изделия требованиям требуют отдельной проверки.

## Локальное обучение

Задача первого классификатора — прочитать код на вырезке ячейки. Для обучения установите вариант пакета `./estd[training]`. В каждой строке входного JSONL укажите `source_sha256` исходного PDF, физическую страницу `page`, относительный путь `crop`, контрольную сумму `crop_sha256`, проверенную по изображению метку `label` (МК, ОК или КЭ), `reviewed: true` и `split` (`train` либо `test`). Можно добавить координаты и идентификаторы пунктов ГОСТа в `normative_refs`. Все страницы одного PDF должны принадлежать одной выборке.

```sh
python -m estd.learning reviewed.jsonl --output model
```

Команда обучает небольшую полносвязную нейросеть на изображениях текста. Совпадающие после нормализации изображения учитываются по одному разу, повторы обучающих изображений исключаются из проверки. Метрики с результатом по каждому уникальному контрольному фрагменту записываются в `metrics.json`, веса — в `form-model.npz`. Передайте путь к весам в `analyze_pdf(..., form_model=...)`. В отчёте появятся хеш модели и отдельное предсказание рядом с прочитанным кодом. Для применения весов достаточно основных зависимостей.

Поиск неподписанных форм, классификация произвольных чертежей, полный нормоконтроль и обучение языковой модели остаются отдельными задачами. Оценка чтения кодов на вырезках характеризует только этот этап. Полноту обнаружения форм проверяют на независимо размеченных полных листах, включая пропуски и неизвестные виды.
